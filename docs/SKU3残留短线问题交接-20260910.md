## 二、显示硬件真相（本日实测，重要）

- 屏幕实际是 **1280×480、RGB888（24bpp）、stride=3840**，双 framebuffer 交替 PAN：
  - fb0=0x41000040，fb1=0x411c2040（间距 0x1C2000）
  - LVGL DIRECT 模式，两块绘制缓冲就是这两块 fb；两 fb 间无背板同步
- 之前一直以为 1280×720 RGB565 是错的（曾导致 CPU 直读 fb 全是乱码）
- bg.jpg 1280×480 与屏幕 1:1，素材没尺寸问题
- 应用层可用 `AICFB_GET_SCREENINFO`（mpp_fb_open/mpp_fb_ioctl，含 mpp_fb.h）查真实屏幕信息

## 五、残留短线问题（未解决，主线索已到关键点）

### 现象
- menu/updown 数值页调温换线后，下划线**右端**出现一小段"比线粗一点点"的灰/白残留，**不呼吸**，恒定在屏，调值瞬间会消失一下再出现
- toastcolor 分量设置同样换线但**无**残留；模拟器（SDL）无残留
- 禁呼吸实验：menu 页关呼吸后残留**不可见**（线常亮时斑块混在线里）

### 已定位的事实（全部实测）
1. 灰斑精确位置：**x393~437、y328..332**（线是 y328..331 共 4 行、右端 x=408；斑多一行且越过线端→"粗一点点、在右端"）
2. 恒定亮度 168~203 灰，**不随呼吸变化**（线从 255→0 全程斑不动），**两块缓冲都有**，**叠在线上面**（255 白线被压成 190）
3. 95 切换（短/长线切换）后额外出现一段 **x412~434、y329~331 的纯白条（255）**，两缓冲都有，呼吸到 0 仍在
4. **素材全部排除干净**：bg.jpg、div2bk.png（面板底图）、underline.png/underline_120x4.png（右端 alpha 全 FF）——用 PowerShell System.Drawing 逐像素验证过
5. 非图片对象、页面无自定义新增控件、切换代码与 toastcolor 同款（HIDDEN 标志加减），差异是**线端压着 ℃ 大字形单位标签**（temp_label 在 (372,281)，线端 x408）
6. 用户确认：℃ 标签本身**在呼吸**

### 主流理论（待最后验证）
**℃ 字形墨迹溢出标签声明框**（字体下降度溢出）：呼吸失效区只覆盖标签声明框（约到 y327），溢出行（328~332）被整页重绘/换线重绘按**当时透明度**画上去后**冻结不再更新**→ 成为不呼吸的静态斑。toastcolor 的单位（g/根）字形小不压线端所以没有。禁呼吸时线常亮、斑融进线里看不见，所以实验"有效"。
- 矛盾点：斑不呼吸 vs 用户说 ℃ 在呼吸——用"字形溢出部分不跟随呼吸"解释（字形主体呼吸，底部溢出行冻结）
